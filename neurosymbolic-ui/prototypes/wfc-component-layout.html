WFC Component Layout

A bento grid of 8 regions, each filled by an actual, live, running component from this repo's own library (components/… — the same files index.html's gallery serves), not a placeholder. Regions form an adjacency graph (hero spans touch four others, corner frames touch two), and WFC resolves which real component occupies which region under a grammar built from what these components actually are — their declared role, and that no two regions can run the identical component at once. Click a region's SWAP to try a different legal component there; only neighbours that are no longer legal re-collapse. The iframe itself is still fully live — drag, hover, click the component inside it as normal.

R1 · ROLEEach region only draws from its own role's pool — HERO regions always get a generative/ambient piece, WIDGET regions an interaction accent, FRAME regions a decorative HUD edge.
R2 · NO DOUBLESA specific component can appear in at most one region across the whole layout — the same global-uniqueness rule as "at most one DELAY" in the patch-chain prototype, generalized to 10 real components.
R3 · ONE FRAME AT A TIMEOf the two FRAME regions, at most one may be occupied — if either resolves to a real component, the other is forced to EMPTY, checked fresh on both sides every propagation pass.
R4 · NO DEAD CORNERSA WIDGET region can only be left EMPTY if at least one of its graph-neighbours is already occupied — propagates along whichever edges this specific region actually has.
