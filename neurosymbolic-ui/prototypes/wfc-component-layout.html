WFC Component Layout

A bento grid of 8 regions, each filled by an actual, live, running component from this repo's own library (components/… — the same files index.html's gallery serves), not a placeholder. Regions form an adjacency graph (hero spans touch four others, corner frames touch two). Describe the layout below; a keyword model scores which components fit, the grammar orders and admits them, and a checker confirms every region still satisfies every rule. The layout map shows other valid fills for those same scores, found without any extra model calls. Click a region's SWAP to try a different legal component there; only neighbours that are no longer legal re-collapse. The iframe itself is still fully live — drag, hover, click the component inside it as normal.

R1 · ROLE0Each region only draws from its own role's pool — HERO regions always get a generative/ambient piece, WIDGET regions an interaction accent, FRAME regions a decorative HUD edge.
R2 · NO DOUBLES0A specific component can appear in at most one region across the whole layout — the same global-uniqueness rule as "at most one DELAY" in the patch-chain prototype, generalized to 10 real components.
R3 · ONE FRAME AT A TIME0Of the two FRAME regions, at most one may be occupied — if either resolves to a real component, the other is forced to EMPTY, checked fresh on both sides every propagation pass.
R4 · NO DEAD CORNERS0A WIDGET region can only be left EMPTY if at least one of its graph-neighbours is already occupied — propagates along whichever edges this specific region actually has.
