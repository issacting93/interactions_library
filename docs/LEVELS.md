# Levels and the level editor

Written 25 Nov 2026 (branch `level-editor`). A level is a data file. A game page builds its world from the file; the editor makes and changes files. There are two kinds: a **field** (a layout, played in the field page) and a **tank stage** (a new place beside the tank's seven, played in the tank). This is the first step of the engine and editor plan (`claude/forge-rust-engine-build-plan.md` in the Forge project).

| What | Where |
|---|---|
| The format, checks and edit commands | `packages/level/level.js` (`window.ForgeLevel`) |
| The editor | `games/the-maw/editor/index.html` |
| Pages that read levels | `games/the-maw/field/index.html` (`#level=draft`, `#level=<name>`); the tank, `world/forges/fish-tool/Cybernetic Ecology.html` (`?stage=draft`, and its menu), through `packages/maw/maw-stages.js` |
| The species a level can name | `packages/level/catalog.js`, generated by `games/the-maw/tools/level-catalog.mjs` from the kit's list (CI checks it is current) |
| Levels | `games/the-maw/levels/*.json`, listed in `index.json` |
| Tests | `games/the-maw/tests/level.test.ts` (vitest), `games/the-maw/tests/level-editor.py` (browser) |

## How it maps to an engine's editor

The editor is laid out the way Unity's and Unreal's are, and each of their ideas has one home here.

| Unity / Unreal | Here |
|---|---|
| Scene file / level (`.unity`, `.umap`) | a level file: `games/the-maw/levels/<name>.json` |
| GameObject / Actor | an entity: `{ id, type, x, y, ...properties }` in `level.entities` |
| Component properties shown by reflection (`[SerializeField]`, `UPROPERTY`) | `ForgeLevel.TYPES`: each type lists its properties once; the inspector and the checks are both made from that list |
| Hierarchy / World Outliner | the outliner (left) |
| Scene view / viewport | the scene (centre): the level from above |
| Inspector / Details | the inspector (right): Inspect, Level, Checks |
| Project window / Place Actors | the Add bar (bottom) |
| Play mode / Play In Editor | Play: the game page itself, given the draft; Stop returns to the edit as it was |
| Undo system / transactions | every edit is a command with its inverse (`ForgeLevel.apply`, `undo`, `redo`); a drag is one step |
| Console errors, Map Check | Checks: `ForgeLevel.validate`; a level with errors cannot be played |
| Automated playtests | Balance: the autopilot plays a stage and reports how it went |
| Prefab / Blueprint | a prefab: a saved group of things, placed and turned as one, changed in every placing at once |
| Editing in play mode | the game is live: a change to the level reaches the running game |
| The 3D scene view | 3D (a field): the game's own view is the scene; press to pick, drag to move, tap to place |

## The file (version 3)

```json
{
  "format": "forge-level", "version": 3, "kind": "field", "name": "One on one", "notes": "", "seed": 7,
  "field": { "shape": "disc", "radius": 100, "crowd": 70 },
  "life": { "ambient": [{ "species": "koi", "count": 7 }] },
  "entities": [
    { "id": "e1", "type": "start", "x": 0, "y": 30 },
    { "id": "e2", "type": "tower", "x": 0, "y": -55, "r": 3.9, "height": 0.82 },
    { "id": "e3", "type": "encounter", "x": 0, "y": -10, "pattern": "charge", "tower": "" }
  ]
}
```

- **Units.** The field is a disc of radius `field.radius` (100). The middle is 0, 0; y runs down the map. A page scales this to its own size, so a level keeps its shape whatever `field.crowd` (how much ground: 40 to 600) is.
- **seed.** Everything a page draws by chance for the layout (plants in a grove, a creature's first heading) comes from it.
- **life.ambient.** The food the field keeps in numbers.
- **Entity types.**

| Type | Properties | Notes |
|---|---|---|
| `start` | | Where the Maw begins. Exactly one |
| `tower` | `r` 1.5 to 25, `height` 0.2 to 0.95 of the tank's depth | A solid the Maw climbs |
| `grove` | `r` 2 to 30, `plants` 1 to 40 | Grown plants, placed from the seed |
| `encounter` | `pattern` (one of the field's 21), `tower` (an id, or empty for the nearest) | Its place is the creature's home. A Hanging Drop goes to its tower |
| `wall` | `len` 4 to 120, `turn` 0 to 179 degrees, `height` 0.05 to 0.5 | Tank stages only. x, y is its middle |
| `landmark` | `kind`: boulder, weed, carcass or vent | Tank stages only. A kind with any placed stands exactly there, in place of its count in the stage's Landmarks |
| `prefab` | `prefab` (a key in `level.prefabs`), `turn` 0 to 359 degrees | One placing of a prefab (below) |

- **Prefabs.** `level.prefabs` is `{ key: { name, parts: [{ type, dx, dy, ...properties }] } }`: each part a thing, placed from the prefab's own middle. A part's `tower` may be `"#2"`, the third part of the same prefab. Pages never see prefabs: `ForgeLevel.expand(level)` gives the level with every placing turned into its parts (ids `<placing>.<n>`, each marked `from`), and the checks say what is wrong with a part of its placing. `makePrefab(level, ids, name)` and `unpackPrefab(level, id)` return the commands that make one and take one apart. A prefab cannot hold the Maw's start or another prefab. A level file always holds the prefabs it uses. The editor also keeps a **library** on the device (`forge-prefabs`): a prefab saved there can be placed in any level, and is copied into that level as it is placed.
- **Nothing is baked.** A file holds recipes and places only.
- **Written one way.** `ForgeLevel.stringify` gives the same text for the same level (the tests hold every file in `levels/` to it), so diffs stay small.
- **Versions.** `ForgeLevel.migrate` brings an older file forward one version at a time (`MIGRATIONS`). A newer file than the build knows is refused. Version 2 added `kind` and `stage`; a version 1 file becomes a field. Version 3 added walls, landmarks, prefabs and a stage's Maw start; nothing in an older file changes.

### A tank stage

`"kind": "stage"` and a `stage` block with the settings a place in the tank has (the same ones as the seven in `maw-stages.js`). The tank lays the place out itself, except for what a stage places: its own **towers**, low **walls**, **landmarks**, and the Maw's **start** (optional; without one the tank finds room). Prefabs of towers and walls work too. Here 100 units is half the tank's short side, so the circle in the editor is the part of the tank every screen shows. When `env.ruins` is on and towers are placed, the tank stands exactly those towers and walls and no others; with nothing placed it rolls its usual ring and walls from its seed. The start holds whether or not towers are on. A tower is never thinner than the tank's least, so on a small screen one may stand wider than drawn.

```json
"stage": {
  "place": "Open water, light", "verb": "Swim", "brief": "…", "trick": "…",
  "roster": { "swift": 30, "koi": 10, "wisp": 12 },
  "crew": { "strider": 3 }, "props": { "boulder": 8, "weed": 10 },
  "env": { "dark": 0.1, "ruins": false },
  "kit": { "eyes": 1 },
  "goal": { "meals": 3 },
  "press": { "upkeep": 8, "prey": 1, "regrow": 45 }
}
```

`ForgeLevel.STAGE` lists these settings once (label, kind, range); the editor's Stage tab and the checks are both made from it. `ForgeLevel.fromStage(stage)` writes one of the seven as a level and `toStage(level, id)` gives it back: the tests hold all seven to coming back the same.

In the tank, `MawStages.EXTRA` holds places beyond the seven. They are never part of `MawStages.LIST`, so a run and Endless are still the seven. The menu lists them after the seven. They come from three places:

| From | Id | Lasts |
|---|---|---|
| A stage file in `games/the-maw/levels/`, named in `index.json` | `lv-<name>` | ships with the game |
| The editor's **+ Add to menu** (`MawStages.add`, kept under `maw-stages-extra`) | `x-<name>` | on that device |
| The level the editor is holding | `draft` (`?stage=draft`; not in the menu) | while it is the draft |

`MawStages.fromLevel(level, id)` is how the tank reads a stage level. `levels/swift-water.json` is an example, made in the editor from The Shoals with two towers placed: delete the file and its name in `index.json` to take it out of the menu.

## Using the editor

Open `games/the-maw/editor/index.html` from a local server (or the deployed site). It works with a mouse or a finger.

- **Add:** choose a kind in the bottom bar, then tap where it goes.
- **Several at once:** Shift-click (or turn **Multi** on, for a finger) adds to the selection. Drag one to move them all; Delete removes them all.
- **Prefabs:** with several selected, name them and press **Make prefab**: they become one piece. **+ Prefab** places it again. Selecting a placing shows the prefab's parts: a change there changes every placing. **Unpack** turns one placing back into separate things.
- **Live:** while the game is open (Play, or 3D), every change is posted to it. What can change under a running game does, at once: in a field, food, towers, encounters (moved, changed, added, removed); in a stage, the roster, crew, landmarks, light, towers and walls, goal and pressure. What is only read at the start (seed, field size, the Maw's start or kit, groves) makes the game load again by itself. On a wide screen Play shows the map and the game side by side.
- **3D** (a field, top right of the scene): the scene becomes the game's own view with a free camera (`#edit=1`). Every placed thing wears a ring. Press one to select it, drag it to move it, tap open ground to place what the Add bar is holding. Drag empty ground to pan, scroll or pinch to zoom, right-drag or Shift-drag to turn.
- **Select and move:** tap a thing; drag it. Drag empty ground to pan; pinch or scroll to zoom; **Fit** shows the whole field. **Snap** sets the step.
- **A tank stage:** New, then *A tank stage* or *Stage like …* (one of the seven to start from). Turn **Towers** on and the scene becomes a map to place towers on. The **Stage** tab has the place's words, roster, crew, landmarks, light, the Maw's kit, the goal and the pressure; the scene shows who lives there, a bar each. **Level** has **+ Add to menu**, which puts it in the tank's menu on this device.
- **Inspect:** the selected thing's place and properties. **Level:** name, seed, field size, food, notes, and **+ Field roster** (fills by rule from the seed). **Checks:** what is wrong; tap one to find it.
- **Play / Stop:** runs a field in the field page and a stage in the tank. Errors must be fixed first.
- **Balance** (a stage's Checks tab): the tank's autopilot plays the stage three times, up to 60, 120 or 240 s each, as fast as the device steps, out of sight. It reports, per run, whether and when the goal was met, meals a minute, the share of strikes that landed, the least energy the Maw fell to, and how often it was caught; then what it mostly ate, and whether the goal's species were among it. The numbers are the autopilot's, which plays plainly, and two runs from one seed are not identical: use them to compare one version of a stage with the next. In the tank it is `__stageBalance(id, { secs, seeds, progress })`, or `?stage=<id>&balance=<seconds>` to have the result posted to the page that holds it.
- **New / Open / Save:** templates; a file or one of `levels/`; a `.json` download. The level being edited is also kept on the device as a draft and comes back on reload.
- Keys: Ctrl/Cmd+Z and Shift+Z, Delete, D (duplicate), arrows (nudge, Shift for more), P (play), F (fit), Esc.

To ship a level with the game: save it, put the file in `games/the-maw/levels/`, and add its name to `index.json`. A stage then appears in the tank's menu for everyone; a field appears in the editor's Open list and plays with `#level=<name>`.

## In a page

```html
<script src="packages/level/level.js"></script>
```

```js
const level = ForgeLevel.parse(text);                 // throws if it is not a level; migrates old versions
const { ok, errors, warnings } = ForgeLevel.validate(level);
const doc = ForgeLevel.doc(level);
ForgeLevel.apply(doc, { op: 'set', id: 'e3', props: { x: 10 } });
ForgeLevel.undo(doc);
```

The field page also writes itself out: `__arena.levelOf()` returns the field as it stands as a level.

## Not done

- **A stage's layout is towers, walls, landmarks and the Maw's start.** Where each species begins is still the tank's (creatures settle by the landmarks). A field level has a full layout and no goal, and no walls.
- **The 3D scene is the field only.** A tank stage is edited on the map and seen by pressing Play. In 3D, a grove's plants are only set again when it is let go (the game loads again), a tower's ring is drawn at its foot, and picking ignores height.
- **Live has gaps:** a stage's kit and start, and a field's groves, seed and start, reload the game. Moving a tower in a running field lays the walkers' world out again, which can unseat a creature that was climbing it.
- The published Endless build (`games/the-maw` build) does not read stage files; only the tank page does.
- No look or weather in the format yet. A stage's forest (`env.forest`) is kept as it is but cannot be edited.
- **The machine garden** (machines, ground cover, weather) is not in the repo, so none of it can be placed.
- **The scene is a map,** not the game's 3D view. Play is how the level is seen as it will look.
- **The engine does not hold the level.** The field page builds its JavaScript world from the file. Commands in, events out (the Rust side) is still ahead.
- **A run does not replay exactly from a level's seed:** the field's patterns still use `Math.random`.
- No painting of ground. The prefab library is per device, not shared between people. No balance run for a field.
- Seen in headless Chrome only: not on a real GPU, a phone or Safari.
