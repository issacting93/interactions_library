## Ecosystem scan — what's worth taking, what's worth dropping

The most consequential finding for this library: all GSAP plugins are now free on CDN — including Draggable, MorphSVG, and Physics2D — which removes the old licensing reason to avoid it. But your `transmute.md` is right that CDN imports are the weak link, and notably **signal-wheel and radial-depth both violate your own zero-dependency rule** by importing anime.js v4 from jsdelivr at runtime. If that CDN hiccups, the spring snap and the entire bloom mechanic silently die — exactly the "graceful degradation = broken and doesn't say so" failure mode your doc names. Worth fixing across the library.

Two genuinely new things worth adopting instead of any library. First, CSS `linear()` lets you sample a real spring equation (mass, stiffness, damping) into points and hand them to CSS as an easing curve — true spring motion with no JS at runtime. That's the right tool for your *non-interactive* transitions (label fades, chrome reveals). The caveat matters for your work though: linear() is a precomputed snapshot; for interactive motion that needs to read current velocity and continue from it, a runtime spring is still required — so your drag-and-release mechanics stay hand-rolled. Second, the native Animation Timeline API for scroll-driven work is maturing, though animation-trigger is still Chrome/Edge only as of mid-2026 — fine for prototypes, not for the portfolio.

On anime.js itself: v4 is a reasonable choice where you do want a library — v4 reached performance parity with GSAP, and active development continues into 2026. But for this library's aesthetic, the 12-line semi-implicit Euler spring in your own transmute doc does everything the two files actually use anime for, with zero fetch risk. That's what I've used below.

## TRANSMUTE — hex-workspace × signal-wheel

**Phase 1 — grammars.**

*A (hex-workspace).* Mechanic: drag through nodes to trace an ordered selection path. State: one ordered list of indices, plus slot contents. Spatial logic: fixed 2D graph. Fixed point: the layout — nodes never move; selection moves across them. Vocabulary: circles, dashed empties, polyline trace. Honesty check: the hex adjacency edges are garnish — your hit-testing ignores them entirely; any node within radius gets appended regardless of adjacency. You drew a graph but built a lasso. The load-bearing part is the *ordered* trace, and one quiet limitation: `selected.includes(hit)` forbids repetition — a sequence grammar that can't repeat a token.

*B (signal-wheel).* Mechanic: drag an annular ring; angle resolves to zone + value; zone nodes counter-rotate and spring-snap. State: one angle plus a binary polarity. Spatial logic: polar, clock convention. Fixed point: the frame's angle→meaning mapping — the zones are painted on the static tick ring; everything else rotates around that. Load-bearing: the drag annulus and the snap spring. Garnish: the polarity segments are a second, unrelated selection model bolted onto the same instrument.

**Phase 2 — isomorphism.** *A's drag-trace is secretly B's ring-drag.* Both convert continuous pointer motion into a walk through discrete stations. A keeps every station it crosses; B keeps only the last one. The fusion is a wheel that *remembers*.

**Phase 3 — organizing principle.** **Daisy wheel.** The typewriter mechanism: rotate to bring a character to the strike position, strike to write it, the written line accumulates beside the machine. A is a daisy wheel where the finger is the head; B is a daisy wheel with amnesia. The name does work: it decided every argument below (aim ≠ commit, fixed strike position, linear output strip, backspace-as-first-class).

**Phase 4 — the kill.** The conflict: A's selection model (touch any node to append) versus B's (angle at a fixed reader resolves state). **A's free spatial trace dies.** You cannot tap a node to select it — ever. The only aiming input is rotating the wheel; the only committing input is the strike. The cost, said out loud: **random access is gone.** In hex-workspace you could jump from Goal to Session in one 90px drag; here you wind the wheel three detents to get there. Sequence-building is strictly slower. That loss buys the machine: because aim and commit are now separate acts, *repetition* becomes possible — Goal → Constraint → Constraint → Artifact is a legal sequence for the first time.

**What emerged (Phase 5).** Repetition is the honest one: because commit is now a separate act from aiming, sequences like Constraint → Constraint became legal, which neither source could express — hex-workspace structurally forbade it and signal-wheel had no sequence at all. The smoke test confirmed it works, not just that it should. A second, smaller discovery during verification: capping the drag annulus at the frame ring (done to fix the strike-pad collision) means the containment hairline is now also the interaction boundary — the drawn instrument edge and the functional edge coincide, which wasn't planned.

**What I verified numerically:** spring overshoots (peak 67.4° on a 60° target) and settles in 0.8s; angular targeting takes the short path (350° → 360°, not backwards); momentum flicks land one station, gentle nudges stay put; armed-index math across five wrap cases; strike-pad clear of the drag zone after the fix; 10 chips fit the strip; drag band ≥44px in portrait; all IDs unique; zero external fetches; and a headless DOM run of build → strike → repeat → unwrite. **Not verified:** real touch feel on a physical device, and Safari's pointer-capture behavior — both are guesses until you open it on your phone.

**The honest trade-off:** this is slower than hex-workspace for its original job. If quick multi-select was the point, the transmutation made it worse; the machine only earns its cost when *sequence with repetition* is the point — which, given your six primitives are literally prompt-context tokens, reads as a context-composition instrument, closer to BLOOM's territory than the original toy was.

**Most wants tuning next:** the momentum projection horizon (`velEMA * 0.15`). At 0.15s a hard flick lands one station; raising it toward 0.3 makes flicks skip two or three, which changes the instrument's whole temperament from typewriter to jog-dial. That constant is the personality knob.

One library-hygiene item worth acting on regardless: signal-wheel and radial-depth both fetch anime.js v4 from jsdelivr at runtime, which your own transmute doc classifies as a failure point — and the 12-line Euler spring covers everything those files use it for. If you do want a library elsewhere, the situation changed: GSAP's full plugin set (Draggable, MorphSVG, Physics2D) went free, and for non-interactive transitions CSS `linear()` now gives you true sampled-spring easing with no runtime JS at all — though interactive drag-release still needs a live integrator, since linear() can't inherit velocity.
